Heritage Monitoring and Registration System

Flutter FastAPI PyTorch Firebase DETR

A cross‑platform field‑survey system that integrates national heritage data, AI‑based damage detection, and real‑time cloud synchronization.

The project modernizes Korea’s cultural‑heritage survey workflow by converting paper inspections into a fully digital, AI‑assisted platform. Built with Flutter (Web/Android/iOS) and a FastAPI backend, it integrates the National Heritage Service Open API, a PyTorch‑based detector, and Firebase real‑time databases to support end‑to‑end survey and registration.

Official records are retrieved through a FastAPI proxy that converts National Heritage Service XML into structured JSON, enabling multi‑criteria search (heritage type, region, keyword) with infinite pagination. Each asset exposes designation category, ownership, managing agency, official address, and geographic coordinates.

A core feature is the AI‑powered damage module using a custom DETR‑based PyTorch model to detect four structural deterioration types—cracks, splits, biological decay, and crushing/burst damage. On‑site images uploaded from the Flutter app are processed by the backend and returned with boxes, labels, confidence scores, and an automatically assigned severity grade (A–D). Results are stored in Firebase with component name, location, inspector notes, and timestamps.

The inspector workflow comprises three structured tabs:

  • Field Survey: basic info, metadata, site photos, and damage detection
  • Inspector Notes: preservation history, survey results, and management actions
  • Comprehensive Assessment: aggregated damage analysis, severity classification, and AI-assisted insights

All updates are synchronized in real time using Firestore streams, ensuring consistent multi-device collaboration during field inspections. Photos and damage records are stored in Firebase Storage, and edit histories are automatically logged for auditability.

The system demonstrates practical integration of cross-platform UI, REST API pipelines, real-time cloud data synchronization, and custom deep-learning inference inside a production-ready workflow. It showcases the feasibility of scalable digital transformation for cultural-heritage management and lays the foundation for future extensions such as GIS-based damage maps, offline-first mobile modes, and multi-language interfaces.

Tech Stack: Flutter 3.35.1, Dart 3.9.0, Firebase (Firestore/Storage), FastAPI, Python 3.10+, PyTorch, DETR (ResNet‑50), Docker, Docker Compose, Nginx, XML→JSON proxy

Role & Contributions

  • Architected end‑to‑end system with Flutter (Web/Android/iOS), FastAPI backend, and Firebase real‑time database
  • Implemented DETR‑based damage detection (ResNet‑50) with class‑specific thresholds and NMS for 4 damage types
  • Designed interactive survey UI: bounding box overlays, thumbnail grid, real‑time stats dashboard
  • Built image pipeline with Firebase Storage and caching/resizing proxy
  • Developed edit‑history tracking (field‑level logs) with StreamBuilder‑based real‑time sync

Key Metrics

  • Inference latency: ~800–1200ms (CPU), ~200–400ms (GPU) per image
  • API response: <150ms (heritage search), <2s (AI detection)
  • Sync delay: <500ms (Firestore real‑time updates)
  • Model: DETR (ResNet‑50), 4 classes, class‑specific conf 0.15–0.30, NMS IoU 0.1, ~552MB
  • Coverage: Single codebase → Web, Android, iOS; tested 10+ concurrent users
