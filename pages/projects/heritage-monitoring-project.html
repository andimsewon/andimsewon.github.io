Heritage-LLaVA: Multimodal Damage Detection for Cultural Heritage

Flutter FastAPI PyTorch Firebase DETR

Problem

Korea's cultural-heritage survey workflow was paper-based: inspectors recorded site condition and damage by hand, with no structured way to track designation status, ownership, or damage severity over time, and no shared real-time view across inspectors in the field.

Approach

Built a cross-platform field-survey system that converts paper inspections into a fully digital, AI-assisted platform. Flutter (Web/Android/iOS) provides the field UI; a FastAPI backend integrates the National Heritage Service Open API (via an XML→JSON proxy for multi-criteria search) and a custom DETR-based PyTorch model for damage detection; Firebase provides real-time storage and sync.

The damage-detection model classifies four structural deterioration types — cracks, splits, biological decay, and crushing/burst damage — from on-site photos, returning bounding boxes, labels, confidence scores, and an automatically assigned severity grade (A–D). The inspector workflow is organized into three tabs: Field Survey (basic info, metadata, site photos, damage detection), Inspector Notes (preservation history, survey results, management actions), and Comprehensive Assessment (aggregated damage analysis and severity classification). All updates sync in real time via Firestore streams, with edit histories logged automatically for auditability.

Result

The damage-detection model reaches F1 0.89 across the four deterioration types. A patent covering the damage-detection method has been filed jointly by the Natural Language Learning Lab (Jeonbuk National University) and the Korea Heritage Service, and the software is registered for copyright. The system is in operational use at the Korea Heritage Service.

  • Inference latency: ~800–1200ms (CPU), ~200–400ms (GPU) per image
  • API response: <150ms (heritage search), <2s (AI detection)
  • Sync delay: <500ms (Firestore real‑time updates)
  • Model: DETR (ResNet‑50), 4 classes, class‑specific conf 0.15–0.30, NMS IoU 0.1, ~552MB
  • Coverage: Single codebase → Web, Android, iOS; tested 10+ concurrent users

My Role

I architected the end-to-end system — the Flutter frontend, the FastAPI backend, and the DETR-based damage-detection pipeline — including the interactive survey UI, the image pipeline, and real-time edit-history tracking.

Tech Stack: PyTorch · LLaVA · CLIP · Detectron2 · FastAPI
